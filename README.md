# AFTER HOURS · 칵테일 지식 라운지

**426개의 칵테일에서 취향에 맞는 한 잔을 찾고, 레시피와 설명 자료를 근거로 대화하는 RAG 서비스.**

TheCocktailDB의 재료·분량·제조법과 위키백과 설명 자료를 활용한다. 사용자는 칵테일을 직접 선택하거나 자연어 조건·보유 재료로 찾은 뒤, 해당 칵테일에 대해 질문할 수 있다.

> 전체 레시피 탐색 대상은 426개이며, 사전에 설명 문서 연결을 검토한 항목은 104개다. 나머지 322개도 기본 레시피로 답변하고, 질문에 필요한 추가 문서를 검색한다. 426개 전체의 설명 문서 검토가 완료됐다는 의미는 아니다.

## 주요 기능

| 기능 | 동작 |
|---|---|
| 칵테일 라운지 | 이미지, 분류, 잔, 재료·분량·제조법과 대화 화면 |
| 조건으로 찾기 | 자연어에서 재료 포함·제외·알코올 여부를 추출하고 실제 데이터로 후보 검증 |
| 내 재료로 만들기 | 보유 재료와 레시피를 비교하고 부족한 재료가 0~2개인 칵테일 표시 |
| 문맥을 반영한 대화 | 이름이 생략되면 선택한 칵테일을 대상으로 이해하고 최근 대화를 참고 |
| 외부 자료 수집 | 검색어 생성 → 위키백과 검색 → 후보 선별 → 본문 확보 |
| 근거 기반 답변 | 선택한 칵테일의 기본 정보와 연결된 문서 청크로 답변 |
| 인용·출처 표시 | 답변에서 인용한 번호의 제목·원문 링크만 표시하고 같은 URL은 묶음 |
| 캐시·증분 저장 | 위키백과 응답 재사용, 새로 추가되거나 변경된 청크만 임베딩 |
| 오류 안내 | 자료 확보·답변 생성 진행 표시, 추가 수집 실패 시 기존 자료로 답변 시도 |

화면은 다크 네이비와 골드 색상으로 구성했다. 상단 탐색 버튼으로 화면을 전환하고, 검색 결과의 **이 칵테일과 대화하기**를 누르면 해당 칵테일의 라운지로 이동한다. 자연어 검색 결과는 페이지당 9개, 보유 재료 결과는 페이지당 6개를 표시한다.

## 데이터 구성

| 구분 | 개수 | 의미 |
|---|---:|---|
| 수집·정제한 칵테일 | 426개 | 현재 전체 선택·검색·재료 비교 대상 |
| 사전 설명 문서 연결 검토 완료 | 104개 | 자체 설명 문서를 확보하고 연결을 검토한 항목 |
| 기본 레시피부터 제공 | 322개 | 기본 정보로 답변하며 추가 문서 검색을 시도하는 항목 |
| 초기 항목별 문서 연결 | 104개 | 같은 원문을 여러 칵테일이 공유할 수 있음 |
| 초기 고유 원문 | 95개 | 사전 검토 자료 기준 |
| 초기 설명 문서 청크 | 484개 | 1,000자·중첩 200자 설정 기준 |
| 최근 확인한 설명 문서 컬렉션 | 524개 | 초기 484개와 실시간 추가분 40개 포함 |

524개는 2026-10-22 사용자 환경에서 확인한 **청크 수**이며, 문서 수나 모든 환경의 고정값이 아니다. 새 환경에서 초기 자료만 색인하면 484개로 시작한다. 사용 중 추가 문서 수집에 따라 개수가 바뀐다.

### 104개에서 426개로 확장한 이유

처음에는 설명 문서 연결을 검토한 104개만 서비스했다. 문서 후보가 연결된 118개를 검토해 104개를 선정하고, 잘못된 대상 연결 등 4개를 제외했으며, 레시피 차이·설명 부족 등 10개는 보류했다.

이후 레시피 검색과 보유 재료 비교의 범위를 넓히기 위해 전체 426개를 탐색 대상으로 확장했다. 기존 104개 목록과 문서는 보존하고, 전체 서비스 목록을 `cocktails_all.json`으로 따로 생성한다. 사전 검토 결과는 신규 탐색 목록과 구분한다.

- **설명 문서 검토 완료:** 기존 자체 설명 문서를 기본으로 유지하고 관련 문서를 추가 검색한다.
- **기본 레시피 · 추가 자료 검색:** 레시피로 확인되는 내용에 답하고, 확보하지 못한 유래·역사 등은 추측하지 않도록 한다.

### 원천 자료와 품질 확인

- [TheCocktailDB](https://www.thecocktaildb.com/): 이름, 분류, 알코올 여부, 잔, 재료·분량, 제조법, 이미지 URL, 원문 URL
- [한국어 위키백과](https://ko.wikipedia.org/)·[영어 위키백과](https://en.wikipedia.org/): 유래, 재료, 제조 기법 등 설명 자료

수집한 426개에서 ID 중복·누락, 이름 누락, 재료 전체 누락, 제조법 누락이 없는 것을 확인했다. 분량이 비어 있는 재료 109건은 추정하지 않고 미기재로 유지했다.

외부 데이터와 이미지의 권리는 제공처별 조건을 따른다. 원문·이미지의 재배포 또는 서비스 공개 전에는 해당 이용 조건과 라이선스를 별도로 확인한다.

| 구분 | 사용 기술 |
|---|---|
| 실행 환경 | Windows, Python 3.12.10, Git Bash |
| 화면 | Streamlit 1.62.0, HTML·CSS |
| 처리 흐름 | LangGraph 1.2.10 |
| 모델 연동 | LangChain OpenAI, SSAFY GMS의 OpenAI 호환 API |
| 임베딩 | text-embedding-3-small, 연결 테스트 기준 1,536차원 |

| 수집·설정 | Requests, python-dotenv |

모델 ID는 `.env`의 `GMS_MODEL`로 조정한다. 설정 예시는 `gpt-6-astra`이며, GMS에서 지원하는 정확한 ID를 사용한다. 주요 패키지 버전은 `requirements.txt`, 전체 설치 환경은 `requirements-lock.txt`에 기록한다.

## 처리 구조

LangGraph는 다음 세 노드로 동작한다.

```text
collect → retrieve → generate
```

1. **collect:** 선택한 칵테일·질문·최근 대화로 검색어를 생성한다. 자체 이름을 항상 검색하고, 사전 자체 문서가 없으면 `(cocktail)` 보완 검색도 수행한다. 제목·요약으로 후보를 선별한 뒤 본문을 확보하고 변경된 청크를 저장한다.
2. **retrieve:** 기본 정보 1개를 항상 근거에 포함한다. 설명 문서는 선택한 `cocktail_id`로 제한해 최대 `top_k`개를 검색하고 중복 ID·동일 본문을 제외한다. 기본 정보 벡터가 아직 없으면 로컬 원본 레시피를 사용한다.
3. **generate:** 선택한 칵테일·최근 대화·현재 근거를 명시적으로 전달한다. 제공된 자료만으로 답하도록 지시하고 인용 번호의 유효 범위를 검사한다. 실제 인용된 출처는 프로그램에서 별도로 표시한다.

최근 대화는 최대 6개 메시지, 메시지당 최대 2,000자를 참고한다. 이전 답변은 질문의 맥락일 뿐 사실의 근거로 사용하지 않도록 지시한다.

### 벡터 컬렉션과 저장 정책

| 컬렉션 | 내용 | 최근 확인 수 |
|---|---|---:|
| `cocktail_metadata` | 전체 칵테일의 검색용 텍스트 | 426개 |
| `cocktail_documents` | 칵테일에 연결된 외부 문서 청크 | 524개 |

- 청크 ID: `칵테일ID:언어:페이지ID:청크번호`
- 내용·메타데이터·임베딩 모델의 해시가 같으면 재임베딩하지 않는다.
- **현재 `build_vector_store.py`는 입력 파일에 없는 기존 데이터를 자동 삭제하지 않는다.** 실시간 추가 자료를 보존하면서 입력 자료를 추가·갱신한다.
- `index_documents.py`는 전달받은 원문의 청크를 갱신하고, 해당 원문의 청크 수가 줄면 남은 이전 청크를 정리한다. 전달하지 않은 다른 원문은 유지한다.
- 위키백과 검색·본문 응답은 하루 동안 캐시한다. 검색어 생성·문서 선별 모델 응답에는 별도 캐시가 없다.

## 설치와 실행

모든 명령은 **Windows 프로젝트 루트의 Git Bash**에서 실행한다.

### 1. 가상환경과 패키지

```bash
python -m venv .venv
./.venv/Scripts/python.exe -m pip install -r requirements.txt
./.venv/Scripts/python.exe -m pip check
```

현재 주요 패키지 목록:

```text
requests==2.34.2
python-dotenv==1.2.4
langchain-core==1.6.13
langchain-openai==1.4.3
langchain-chroma==1.1.0
chromadb==1.5.9
langgraph==1.2.10
streamlit==1.62.0
```

정상 동작한 전체 설치 버전을 복원하려면 `requirements.txt` 대신 `requirements-lock.txt`로 설치한다. 다른 운영체제에서는 잠금 파일의 패키지 호환성을 확인한다.

### 2. 환경 변수

```bash
cp .env.example .env
```

`.env`를 열어 본인 설정을 입력한다.

```dotenv
GMS_KEY=your_gms_api_key
GMS_BASE_URL=https://gms.ssafy.io/gmsapi/api.openai.com/v1/
GMS_MODEL=gpt-6-astra
GMS_EMBEDDING_MODEL=text-embedding-3-small
WIKI_CONTACT=your-email@example.com
```

실제 API 키는 커밋하지 않는다. `WIKI_CONTACT`에는 본인의 영문 이메일 또는 URL을 입력한다.

### 3. 검색과 화면 설정

루트의 `config.json`:

```json
{
  "chunk_size": 1000,
  "chunk_overlap": 200,
  "top_k": 5
}
```

`chunk_overlap`은 0 이상, `chunk_size` 미만이어야 한다. `top_k`는 외부 문서 청크 수이며 기본 정보는 별도로 포함한다.

루트에 `.streamlit` 폴더를 만들고 `config.toml`을 준비한다.

```toml
[theme]
base = "dark"
primaryColor = "#D6B67A"
backgroundColor = "#0A121D"
secondaryBackgroundColor = "#132235"
textColor = "#E7EDF3"
font = "sans serif"
```

커스텀 CSS와 기본 위젯이 같은 다크 색상을 사용하도록 이 설정도 함께 적용한다.

### 4. 새 환경에서 데이터와 색인 준비

최소한 다음 원본·검토 데이터를 프로젝트에 배치한다.

- `data/processed/cocktails.json`
- `data/service/cocktails.json`
- `data/service/documents.json`

기존 104개 목록을 유지하면서 전체 426개 목록을 생성한다. 이 단계에는 API 호출이 없다.

```bash
./.venv/Scripts/python.exe scripts/expand_catalog.py
```

예상 결과:

```text
전체 검색 대상: 426개
검토한 설명 문서 연결 있음: 104개
기본 레시피부터 제공: 322개
```

초기 문서 청크를 준비하고 벡터 DB를 구축한다.

```bash
./.venv/Scripts/python.exe scripts/chunk_service_documents.py
./.venv/Scripts/python.exe scripts/build_vector_store.py
```

초기 자료가 같으면 기본 정보 426개, 설명 문서 청크 484개가 준비된다. 이미 추가 수집 자료가 있는 DB에서는 그 자료가 보존되므로 총 청크 수가 더 많을 수 있다. 임베딩 대상에 대해서만 API 크레딧이 사용된다.

### 5. 기존 104개 환경을 426개로 확장

확장 버전의 코드를 적용하고 기존 서버를 종료한 뒤 실행한다. 기존 `scripts` 폴더나 데이터 폴더 전체를 삭제하지 않는다.

```bash
./.venv/Scripts/python.exe scripts/expand_catalog.py
./.venv/Scripts/python.exe scripts/build_vector_store.py
```

기존 104개 정보가 동일하면 104개는 재사용하고 신규 322개를 임베딩한다. 사용자 환경에서 초기 문서 484개는 모두 재사용하고 기존 추가 청크 40개도 유지한 것을 확인했다.

### 6. 화면 실행

```bash
./.venv/Scripts/python.exe -m streamlit run app.py
```

이미 데이터와 색인이 준비된 환경에서는 이 명령만 실행하면 된다. 터미널에 표시된 로컬 주소로 접속한다. 코드·모델·설정을 변경한 뒤에는 서버를 종료·재실행하고 필요하면 브라우저에서 `Ctrl+Shift+R`로 새로고침한다.

**대화 모델만 변경하면 재임베딩할 필요가 없다.** 임베딩 모델을 바꾸면 새 경로나 새 컬렉션으로 전체 색인을 재구축해야 한다. 기존 모델의 벡터와 혼용하지 않는다.

## 사용 예시

### 칵테일 라운지

Mojito를 선택하고 질문한다.

- `어디에서 유래했어?`
- `민트는 어떻게 사용해?`
- `그걸 잘게 찢어도 돼?`
- `최초로 판매한 날짜를 연월일까지 알려줘.`

이름을 생략하면 현재 선택한 칵테일을 대상으로 해석한다. 정확한 날짜처럼 근거에 없는 정보는 확인 불가를 안내해야 한다. 칵테일별 기록은 세션 안에서 분리하고, 현재 대화만 비울 수 있다.

신규 항목인 A1 등은 `재료와 분량, 제조법을 알려줘.`로 기본 레시피 답변을 확인할 수 있다. 유래 질문은 실제 확보한 설명 문서에 따라 답변 가능 여부가 달라진다.

### 조건으로 찾기

`진이 들어가고 크림은 없는 칵테일 찾아줘.`

모델이 실제 데이터에 있는 재료명으로 조건을 추출하면 코드가 전체 426개의 레시피를 비교한다. 표시된 조건을 확인하고 결과 카드에서 **이 칵테일과 대화하기**를 선택한다.

지원 조건은 재료 전체 포함(AND), 재료 제외, 알코올 여부다. OR 조건, 맛, 도수, 가격 등 현재 지원하지 않는 조건에는 추가 확인을 요청한다. 이전 104개 데이터에서는 위 예시로 23개를 확인했지만, 426개로 확장한 뒤의 결과 수는 별도로 계산되므로 23개로 고정하지 않는다.

### 내 재료로 만들기

`Gin`, `Campari`, `Sweet Vermouth`를 선택하면 Negroni의 기재 재료를 모두 보유한 것으로 표시한다. Campari를 제외하고 부족한 재료 1개까지 허용하면 부족한 재료에 Campari가 표시된다.

레시피·분량·원문 링크를 판단 근거로 제공한다. 재료 이름의 대소문자는 통합하지만 보유량, 대체 재료, 알레르기 안전성까지 판단하지는 않는다.

### 테스트용 응답으로 확인한 결과

- Streamlit 1.62.0에서 전체 426개 데이터 로드
- 조건 검색 → Aviation 선택 → 첫 질문·후속 질문의 화면·선택·기록 유지
- 보유 재료 결과 → 칵테일 대화 이동
- 문서가 없는 신규 항목에서 기본 레시피를 근거로 답변하는 처리 경로
- 외부 수집 실패 시 기존 기본 정보로 답변을 계속하는 처리 경로
- 전체 데이터 준비 시 기존 목록·검색 텍스트 보존
- 기존 추가 문서 미삭제, 동일 데이터 재실행 시 재임베딩 생략

테스트용 응답 검증은 실제 GMS 생성 품질 평가를 대신하지 않는다. 확장 후 신규 항목의 실제 답변 품질과 설명 문서 연결은 추가 검토가 필요하다. 위 기록은 정량 정확도나 모든 질문의 정답을 보장하지 않는다.

## 현재 제한과 보완할 점

- 전체 426개에 레시피는 있지만 사전 설명 문서 연결을 검토한 항목은 104개다. 나머지는 질문 시 문서 확보를 시도한다.
- 신규 검색 문서는 모델이 제목·요약으로 선별한다. 사람 검토 완료 표시로 자동 승격하지 않으며, 원문과 레시피의 일치 여부는 추가 검토가 필요하다.
- 기본 정보 벡터는 저장하지만 자연어 필터는 JSON 원본을 직접 검증한다. 기본 정보 벡터 유사도로 추천하는 기능은 아직 없다.
- 문서 검색은 `top_k` 기준이다. 거리 임계값, MMR, 재순위화는 적용하지 않았다.
- 글자 수 기준 청킹으로 문장 중간이 잘릴 수 있다. 일부 공유 문서에는 관련 부분 추출 규칙을 사용한다.
- 원천 자료와 위키백과 레시피가 다를 수 있어 출처별 차이를 구분하도록 지시한다. 생성 결과 검토는 필요하다.
- 인용 번호의 범위는 검사하지만 문장별 근거 일치 여부까지 자동 검증하지는 않는다.
- 검색어 생성·문서 선별 모델 응답에는 캐시가 없다. 같은 질문도 검색어와 결과가 달라질 수 있다.
- 대화 기록은 Streamlit 세션에 보관하며 영구 저장·로그인 사용자별 복원은 지원하지 않는다.
- 다중 사용자 동시 문서 갱신과 DB 쓰기는 별도 검증하지 않았다.
- RAG 미적용·적용 비교 평가, 새 환경 전체 실행 확인, 명세서 항목별 최종 점검은 별도 마무리 작업이다.

## 문제 해결

| 증상 | 확인할 내용 |
|---|---|
| `cocktails_all.json` 없음 | 프로젝트 루트에서 `scripts/expand_catalog.py` 실행 |
| 화면에 여전히 104개만 표시 | 확장 버전 `app.py` 적용, `cocktails_all.json` 생성, 서버 재시작 |
| 기본 정보 벡터가 없음 | `scripts/build_vector_store.py` 실행 결과 확인. 답변은 로컬 레시피로도 시도 |
| 설명 문서 없음 안내 | 기본 레시피 사용은 가능. 유래·역사 답변에는 추가 근거 필요 |
| GMS 502 / Bad Gateway | 일시적인 서버·모델 연결 문제 가능. 모델 ID와 상태 확인 후 재시도 |
| 임베딩 모델 불일치 | 저장 모델과 `.env` 확인. 모델 변경 시 별도 색인 재구축 |
| 검색 결과 선택 후 질문하면 화면 복귀 | 상단 라디오 대신 탐색 버튼을 사용하는 최신 `app.py` 적용 후 서버·브라우저 새로고침 |
| 입력창·드롭다운의 대비가 낮음 | `.streamlit/config.toml`의 다크 테마와 최신 CSS 적용 |
| import 오류 | 기존 `scripts` 파일을 삭제하지 않았는지, 변경한 모듈명을 사용하는지 확인 |
